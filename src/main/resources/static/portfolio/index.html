프로모션 도메인 신규 구축 — 기간형(2.0) → 관리형(3.0)

개요: 브랜드/상품 단위 할인을 등록하면 20여 개 마켓에 가격을 자동 송출하고 주문 정산까지 일관 처리하는 프로모션 도메인을 백엔드 전 영역에서 설계·구현 (2025.11 ~ 운영·고도화 중). 기간형 가격 프로모션(2.0)을 먼저 구축하고, 그 제약을 풀어 관리형(3.0)으로 확장

핵심 판단:

  • 이미 도입돼 있던 Kafka를 걷어내고 AWS SQS FIFO로 교체 — 스트림 처리·이벤트 재소비 없이 "순서 보장 작업 큐"로만 쓰고 있었으므로, 순서·중복 제거를 지원하는 SQS FIFO로 기능 손실 없이 인프라 비용을 줄일 수 있다고 판단하고 실행
  • 주문 시점 가격을 언제든 재현할 수 있도록 상품×프로모션 조합의 계산 결과를 확정 저장(스냅샷) — 주문·정산·송출이 그 한 곳만 읽는 단일 기준
  • 여러 서버가 동시에 상품을 프로모션에 편입하며 생기던 중복·누락을 락이나 유니크 제약이 아니라 FIFO 단일 순차 경로로 해결 — 경합을 막는 대신 경합이 생길 수 없는 구조로

기술 스택: Kotlin Spring Boot Kafka AWS SQS Quartz QueryDSL React PHP (Laravel) MySQL

1단계 — 기간형 프로모션(2.0) 신규 구축 (레거시, 2025.11 ~ 2026.04):

  • 기존 1.0은 마켓에 걸어둔 할인에 내부 정산을 맞추는 내부 관리 기능이라 마켓·내부 양쪽을 따로 수정해야 했음 → 프로모션 세팅에 따라 외부 마켓 가격을 직접 수정·송출해 이중 작업 제거. 엑셀 업로드/다운로드/템플릿, 스케줄러 기반 시작·종료, 기간 중복 체크, 상태 흐름(시작/중지/재시작/연장/종료) 구현
  • 마켓별 상이한 할인 규격(쿠팡·SSG·카카오스타일 최종가 1원 절사, 11번가 할인 타입, 지마켓·옥션 정액) 흡수. 등록 상품이 0건이면 전체 롤백, 상품 삭제 시 외부 채널 가격을 복구하는 동기화 Job으로 마켓과 내부 가격이 어긋나는 상황을 방지 (운영 약 9,200건 처리)

2단계 — 관리형(3.0)으로 확장 (V2 백엔드 단독 설계 + React FE): 2.0은 진행 중에는 상품 가격이 변동되면 안 돼 가격 수정이 막히는 제약이 있었음 → 재계산 통합 로직으로 상품가격·정산기준가·수수료를 상품 단위로 제어해 할인뿐 아니라 판매가 자체를 조정할 수 있게 확장

  • 스냅샷은 대기→진행→만료 상태 흐름과 브랜드 설정이 소속 상품 전체에 자동 반영되는 구조로 설계 (새 상품이 등록되면 자동으로 프로모션에 편입)
  • 프로모션 시작·종료를 스케줄러가 직접 처리하던 방식에서 메시지 큐 이벤트 방식으로 재설계 — 월초 자정에 104만 건이 한꺼번에 몰리는 가격 송출을 속도 조절로 안정 처리
  • 프로모션 가격이 다른 가격 설정보다 우선 적용되어 마켓에 송출되는 규칙을 구현하고, 진행 중인 프로모션을 수정하면 바뀐 가격이 마켓에 자동으로 재송출되게 처리
  • 관리자용 정상가 일괄 수정 기능(엑셀 미리보기, 할인율 역산 근거 표시)과 React 관리자 화면(등록/조회/수정, 셀 단위 편집·엑셀 업로드·이력) 구현
